# 第1章 计算机系统概述

## 1.1 操作系统的基本概念

### 1.1.1 操作系统的概念

操作系统（Operating System，OS）是计算机系统中最基本、最重要的系统软件。它负责管理和控制计算机系统中的硬件与软件资源，合理地组织计算机工作流程，为用户使用计算机提供一个方便、灵活、安全、可靠的工作环境。

从用户角度看，操作系统是用户与计算机硬件之间的接口。用户在操作系统的帮助下能够方便、快捷、安全、可靠地操纵计算机硬件和运行自己的程序。

从资源管理角度看，操作系统是计算机系统资源的管理者。处理机管理、存储器管理、文件管理、设备管理是操作系统的主要功能。

操作系统的定义：操作系统是指控制和管理整个计算机系统的硬件与软件资源，并合理地组织调度计算机的工作和资源的分配，以提供给用户和其他软件方便的接口和环境，它是计算机系统中最基本的系统软件。

### 1.1.2 操作系统的特征

操作系统的基本特征包括并发、共享、虚拟和异步。

**1. 并发（Concurrence）**

并发是指两个或多个事件在同一时间间隔内发生。操作系统的并发性是指计算机系统中同时存在多个运行的程序，因此它具有处理和调度多个程序同时执行的能力。在操作系统中，引入进程的目的是使程序能并发执行。

注意区分并发与并行：并行是指两个或多个事件在同一时刻发生。

**2. 共享（Sharing）**

共享即资源共享，是指系统中的资源可供内存中多个并发执行的进程共同使用。共享可分为两类：

- **互斥共享方式**：系统中的某些资源（如打印机、磁带机），虽然可以提供给多个进程使用，但在一段时间内只允许一个进程访问该资源。这种资源称为临界资源或独占资源。
- **同时共享方式**：系统中的某些资源，允许在一段时间内由多个进程"同时"对它们进行访问。"同时"通常是宏观上的，而在微观上，这些进程可能是交替地对该资源进行访问（即分时共享）。

并发和共享是操作系统两个最基本的特征，两者互为存在条件：资源共享是以程序的并发执行为条件的，若系统不允许程序并发执行，则不存在资源共享问题；若系统不能对资源共享实施有效管理，则必将影响程序的并发执行。

**3. 虚拟（Virtual）**

虚拟是指通过某种技术把一个物理实体变为若干个逻辑上的对应物。物理实体是实的，即实际存在的；而逻辑对应物是虚的，是用户感觉上的事物。用于实现虚拟的技术称为虚拟技术，操作系统中利用了多种虚拟技术来实现虚拟处理器、虚拟内存和虚拟外部设备等。

**4. 异步（Asynchronism）**

异步是指在多道程序环境下，允许多个程序并发执行，但由于资源有限，进程的执行不是一贯到底的，而是走走停停，以不可预知的速度向前推进，这就是进程的异步性。

### 1.1.3 操作系统的发展与分类

**一、手工操作阶段（无操作系统）**

最早的计算机没有操作系统，所有工作都需要人工干预，如程序的装入、运行、结果的输出等。缺点是用户独占全机，CPU等待人工操作，资源利用率低。

**二、批处理阶段**

**1. 单道批处理系统**

引入脱机输入/输出技术（用磁带完成），由监督程序负责控制作业的输入、输出。主要特征：自动性、顺序性、单道性。缺点是CPU和I/O设备的速度不匹配，CPU等待I/O。

**2. 多道批处理系统**

允许多个程序同时进入内存并交替执行。主要特征：多道、宏观上并行、微观上串行。优点是资源利用率高、系统吞吐量大。缺点是用户交互性差、平均周转时间长。

多道程序设计技术是指允许多个程序同时进入内存并运行。多道程序并发执行的本质是：当一个程序因I/O请求而暂停运行时，CPU便立即转去执行另一个程序。

**三、分时操作系统**

分时技术是指把处理器的运行时间分成很短的时间片，按时间片轮流把处理器分配给各联机作业使用。主要特征：同时性、交互性、独立性、及时性。典型系统：UNIX。

**四、实时操作系统**

实时操作系统是指能在规定时间内完成特定功能的操作系统。分为硬实时系统（必须在绝对严格的规定时间内完成）和软实时系统（能接受偶尔违反时间规定）。主要特征：及时性、可靠性。

**五、网络操作系统和分布式操作系统**

网络操作系统把计算机网络中的各台计算机有机地结合起来，提供统一、经济、有效地使用各台计算机的方法，实现各台计算机之间数据的互相传送。

分布式操作系统是指将多台计算机组成一个完整的、功能强大的计算机系统，系统中各台计算机无主次之分，任意两台计算机可以通过通信交换信息。

**六、个人计算机操作系统**

目前最常用的个人计算机操作系统有Windows、Linux、MacOS等。

### 1.1.4 操作系统的运行机制

计算机系统中，通常CPU执行两种不同性质的程序：操作系统的内核程序和用户自编程序。为了保证系统安全可靠，CPU通常有两种运行状态：核心态（管态）和用户态（目态）。

- **核心态（内核态）**：操作系统内核程序运行的状态，可以执行一切指令，访问所有寄存器和存储区。
- **用户态**：用户自编程序运行的状态，只能执行非特权指令，不能直接访问系统资源、改变机器状态。

**特权指令**：指在核心态下才能执行的指令（如I/O指令、设置时钟、置中断屏蔽、清内存、修改状态字、停机等）。

**非特权指令**：指在用户态下可以执行的指令（如算术运算指令、逻辑运算指令、取数存数指令、访管指令等）。

CPU状态的切换通过程序状态字寄存器（PSW）中的状态标志位来实现。

### 1.1.5 操作系统内核

操作系统内核是计算机系统中最底层的软件，它提供操作系统最基本的功能。内核通常包括以下功能：

**1. 时钟管理**：操作系统通过时钟管理向用户提供标准的系统时间，并通过时钟中断管理实现进程的切换等。

**2. 中断机制**：中断机制是操作系统内核最基本、最重要的功能。现代操作系统是靠中断驱动的软件。

**3. 原语（Primitive）**：原语是由若干条指令组成的，用于完成一定功能的一个过程。它与一般过程的区别在于：原语是原子操作，执行过程中不允许被中断。常驻内存。

**4. 系统控制的数据结构及处理**：系统采用各种数据结构来登记状态信息，如作业控制块、进程控制块（PCB）、设备控制块、各类链表、文件控制块等。

内核的体系结构可以分为两大类：大内核和微内核。

- **大内核（宏内核）**：将操作系统的主要功能模块都作为一个紧密联系的整体运行在核心态，从而为应用提供高性能的系统服务。缺点是内核庞大，不易维护和扩展。
- **微内核**：将内核中最基本的功能（如进程管理、中断处理、进程间通信等）保留在内核，而将不需要在核心态执行的功能移到用户态执行。优点是内核小、可靠、易于扩展和移植。缺点是需要频繁地在核心态和用户态之间切换，性能较低。

### 1.1.6 中断和异常

**一、中断的基本概念**

中断（Interrupt）是指计算机运行过程中，当出现某些意外情况需要主机干预时，机器能自动停止正在运行的程序并转入处理新情况的程序，处理完毕后又返回原被暂停的程序继续运行。

中断的作用：
1. 实现CPU与I/O设备的并行工作
2. 实现人机交互
3. 实现多道程序并发执行
4. 实现实时处理

**二、中断的分类**

1. **内中断（异常）**：来自CPU内部的中断信号。
   - 自愿中断（访管中断/软件中断）：执行访管指令（系统调用）时产生。
   - 强迫中断：包括硬件故障（如缺页、断电）和软件异常（如除数为0、非法指令）。

2. **外中断（中断）**：来自CPU外部的中断信号。
   - 可屏蔽中断：通过INTR线发出的中断请求，可通过设置中断屏蔽字来屏蔽。
   - 不可屏蔽中断：通过NMI线发出的中断请求，不能被屏蔽，如电源掉电。

**三、中断处理过程**

1. 关中断，保护断点和程序状态
2. 根据中断向量转入相应的中断处理程序
3. 执行中断处理程序
4. 恢复现场，开中断，返回断点

### 1.1.7 系统调用

系统调用（System Call）是指用户在程序中调用操作系统所提供的一些子功能，它是操作系统提供给用户程序的接口。

系统调用的作用：
- 为用户程序使用系统资源提供统一接口
- 隐藏底层硬件细节，方便用户编程
- 保证系统安全稳定

系统调用与库函数的区别：
- 系统调用运行在核心态，是操作系统提供的服务
- 库函数运行在用户态，是由编程语言提供的封装函数
- 有些库函数封装了系统调用（如printf封装了write系统调用），有些则与系统调用无关（如strlen）

系统调用的处理过程：
1. 用户程序执行访管指令（陷入指令），产生访管中断
2. CPU从用户态切换为核心态
3. 根据系统调用号，转到相应的系统调用处理程序
4. 执行系统调用服务
5. 返回用户程序，CPU切换回用户态

常见系统调用类型：进程控制类、文件操纵类、进程通信类、设备管理类、信息维护类。

### 1.3.4 操作系统结构

1. **分层法**：将操作系统分为若干层，每层只能使用其底层提供的功能。优点是结构清晰、便于调试和维护。缺点是效率较低。

# 第2章 进程管理

## 2.1 进程与线程

### 2.1.1 进程的概念和特征

**一、进程的概念**

进程（Process）是程序的一次执行过程，是系统进行资源分配和调度的一个独立单位。进程由程序段、相关数据段和进程控制块（PCB）三部分组成。

进程和程序的区别：
- 进程是动态的，程序是静态的。程序是存储在磁盘上的一组有序指令的集合，是一个静态的概念；进程是程序在处理机上的一次执行过程，是一个动态的概念。
- 进程具有生命周期，程序可以永久存在。
- 进程具有并发性，而程序没有。
- 一个程序可以对应多个进程，一个进程也可以包含多个程序。

**二、进程的特征**

1. **动态性**：进程是程序的一次执行过程，有创建、运行、消亡的过程，是动态产生、变化和消亡的。
2. **并发性**：多个进程实体同存于内存中，能在一段时间内同时运行。
3. **独立性**：进程是一个能独立运行、独立获取资源和独立接受调度的基本单位。
4. **异步性**：进程按各自独立的、不可预知的速度向前推进。

**三、进程的状态与转换**

进程的五种基本状态：

1. **创建态（New）**：进程正在被创建，尚未进入就绪队列。
2. **就绪态（Ready）**：进程已获得除CPU外的所有必要资源，一旦获得CPU即可运行。
3. **运行态（Running）**：进程正在CPU上运行。
4. **阻塞态（Blocked/Waiting）**：进程正在等待某一事件（如I/O完成）而暂停运行。
5. **终止态（Terminated）**：进程正在从系统中消失。

状态转换：
- 创建态 → 就绪态：进程创建完成，进入就绪队列
- 就绪态 → 运行态：进程被调度程序选中，获得CPU
- 运行态 → 就绪态：时间片用完，或有更高优先级进程抢占
- 运行态 → 阻塞态：进程请求某事件（如I/O请求）而等待
- 阻塞态 → 就绪态：等待的事件发生（如I/O完成）
- 运行态 → 终止态：进程执行完毕或被撤销

注意：不能直接从阻塞态转换为运行态，也不能直接从就绪态转换为阻塞态。

### 2.1.2 进程控制块（PCB）

进程控制块（Process Control Block，PCB）是进程存在的唯一标志。创建进程就是创建PCB，撤销进程就是撤销PCB。

PCB通常包含以下信息：
1. **进程标识符**：唯一标识一个进程（PID）
2. **处理机状态**：包括通用寄存器、指令计数器、程序状态字PSW等
3. **进程调度信息**：进程状态、优先级、调度所需的其他信息
4. **进程控制信息**：程序和数据的地址、进程同步和通信机制、资源清单、链接指针

PCB的组织方式：
- **链接方式**：将具有相同状态的PCB链接成队列
- **索引方式**：为各种状态建立索引表

### 2.1.3 进程控制

进程控制的主要功能是对系统中的所有进程实施有效的管理，包括进程创建、进程终止、进程阻塞与唤醒、进程挂起与激活等。

**一、进程的创建**

创建进程的事件：用户登录、作业调度、提供服务、应用请求。

创建过程：
1. 为新进程申请空白PCB
2. 为新进程分配资源
3. 初始化PCB
4. 将新进程插入就绪队列

**二、进程的终止**

终止进程的事件：正常结束、异常结束、外界干预。

终止过程：
1. 根据进程标识符检索出该进程的PCB
2. 终止该进程及其子孙进程的执行
3. 归还该进程的所有资源给父进程或系统
4. 将该PCB从所在队列中移出

**三、进程的阻塞与唤醒**

阻塞：当进程等待某事件发生时，调用阻塞原语将自己阻塞。
唤醒：当等待的事件发生时，由发现者进程调用唤醒原语将等待该事件的进程唤醒。

### 2.1.4 进程通信

进程通信是指进程之间的信息交换。主要有三种方式：共享存储、消息传递、管道通信。

**一、共享存储（Shared Memory）**

在内存中开辟一块共享空间，相互通信的进程通过对共享存储区的读写来交换信息。

- 基于数据结构的共享：低级通信方式，共享空间存放固定格式的数据结构
- 基于存储区的共享：高级通信方式，共享空间是内存中的一个存储区

**二、消息传递（Message Passing）**

进程间的数据交换以格式化的消息为单位。通过操作系统提供的发送消息/接收消息两个原语进行数据交换。

- 直接通信方式：发送进程直接把消息发送给接收进程
- 间接通信方式（信箱通信）：通过中间实体（信箱）进行通信

**三、管道通信（Pipe）**

管道是指用于连接一个读进程和一个写进程以实现它们之间通信的共享文件（pipe文件）。向管道提供输入的发送进程以字符流形式将大量数据送入管道，而接收进程可从管道中接收数据。

管道通信的特点：
- 半双工通信：数据只能单向流动
- 各进程对管道的访问是互斥的
- 管道中未读数据超出上限时写进程阻塞，管道为空时读进程阻塞

### 2.1.5 线程概念和多线程模型

**一、线程的基本概念**

线程（Thread）是操作系统能够进行运算调度的最小单位，被包含在进程之中，是进程中的实际运作单位。

引入线程的目的：减少程序并发执行所付出的时空开销，提高操作系统的并发性能。

线程与进程的比较：
- 调度：线程是独立调度的基本单位，进程是资源分配的基本单位
- 拥有资源：进程拥有资源，线程（几乎）不拥有系统资源
- 并发性：不仅进程之间可以并发执行，同一进程的多个线程之间也可以并发执行
- 系统开销：线程切换只需保存和设置少量寄存器，开销远小于进程切换
- 地址空间和其他资源：同一进程的各线程间共享地址空间和文件等资源；不同进程间相互独立

**二、线程的实现方式**

1. **用户级线程（User-Level Thread，ULT）**
   - 线程的管理工作由应用程序完成，内核意识不到线程的存在
   - 优点：线程切换不涉及内核态切换，开销小
   - 缺点：一个线程阻塞会导致整个进程阻塞，无法利用多处理机

2. **内核级线程（Kernel-Level Thread，KLT）**
   - 线程的管理工作由内核完成
   - 优点：一个线程阻塞不影响其他线程，可以利用多处理机
   - 缺点：线程切换需要内核态切换，开销大

3. **组合方式**
   - 多对一模型：多个用户级线程映射到一个内核级线程
   - 一对一模型：一个用户级线程映射到一个内核级线程
   - 多对多模型：多个用户级线程映射到多个内核级线程

## 2.2 处理机调度

### 2.2.1 调度的基本概念

处理机调度是对处理机进行分配，即从就绪队列中按照一定的算法选择一个进程并将处理机分配给它运行，以实现进程的并发执行。

调度的层次：
1. **高级调度（作业调度）**：按照某种规则从外存上处于后备状态的作业中挑选作业，分配内存等必要资源，建立相应进程。频率低。
2. **中级调度（内存调度）**：将暂时不能运行的进程调至外存等待（挂起），当内存空闲时再将其调回内存。目的是提高内存利用率和系统吞吐量。
3. **低级调度（进程调度）**：按照某种策略从就绪队列中选取一个进程，将处理机分配给它。频率高。

不能进行进程调度与切换的情况：
1. 在处理中断的过程中
2. 进程在操作系统内核程序临界区中
3. 其他需要完全屏蔽中断的原子操作过程中

### 2.2.2 调度的时机、切换与过程

进程调度和切换的过程：
1. 保存处理机现场信息
2. 按某种算法从就绪队列中选取进程
3. 将处理机分配给选中进程（恢复现场）

调度时机：
- 主动放弃处理机：进程正常终止、进程发生异常终止、进程主动请求阻塞
- 被动放弃处理机：时间片用完、有更高优先级进程进入就绪队列

### 2.2.3 调度算法评价指标

1. **CPU利用率**：CPU有效工作时间 / 总时间
2. **系统吞吐量**：单位时间内完成的作业数
3. **周转时间**：从作业提交到作业完成的时间。包括等待时间（在就绪队列中）和运行时间。
   - 平均周转时间 = 各作业周转时间之和 / 作业数
   - 带权周转时间 = 作业周转时间 / 作业运行时间
4. **等待时间**：进程在就绪队列中等待的时间总和
5. **响应时间**：从用户提交请求到系统首次产生响应的时间

### 2.2.4 调度算法

**一、先来先服务（FCFS）算法**

按照进程/作业到达的先后顺序进行调度。是非抢占式算法。

- 优点：简单、公平
- 缺点：对短作业不利，平均周转时间长。存在"护航效应"（长作业先到导致后面短作业长时间等待）

**二、短作业优先（SJF/SPF）算法**

优先调度预计运行时间最短的进程/作业。分为抢占式（SRTF）和非抢占式。

- 优点：平均周转时间最短
- 缺点：长作业可能出现"饥饿"现象。需要预知作业运行时间，实际上很难准确估计

**三、优先级调度算法**

根据进程/作业的优先级进行调度。分为抢占式和非抢占式。

优先级类型：
- 静态优先级：创建时确定，运行期间不变
- 动态优先级：运行期间可根据情况变化（如等待时间增长可提高优先级）

**四、高响应比优先算法（HRRN）**

响应比 = (等待时间 + 要求服务时间) / 要求服务时间 = 1 + 等待时间 / 要求服务时间

兼顾了短作业和长作业：短作业要求服务时间短，响应比高；长作业等待时间增长，响应比也会提高。

**五、时间片轮转（RR）算法**

将所有就绪进程按FCFS排成一个队列，每次调度时将CPU分配给队首进程，让其执行一个时间片。时间片用完后，由时钟中断引发调度。

时间片大小的选择：过大则退化为FCFS；过小则切换频繁，系统开销大。

**六、多级反馈队列调度算法**

设置多个就绪队列，每个队列优先级不同，时间片大小也不同。新进程进入最高优先级队列，若在一个时间片内未完成，则降入下一级队列。高优先级队列优先调度，只有高优先级队列为空时才调度低优先级队列。

## 2.3 同步与互斥

### 2.3.1 基本概念

**临界资源**：一次仅允许一个进程使用的资源。

**临界区**：进程中访问临界资源的那段代码。

**同步**：多个进程因为需要在某些位置上协调它们的工作次序而等待、传递信息所产生的制约关系。

**互斥**：当一个进程进入临界区使用临界资源时，另一个进程必须等待，直到该进程退出临界区。

临界区访问原则：
1. **空闲让进**：临界区空闲时，允许一个进程立即进入
2. **忙则等待**：临界区已有进程时，其他进程必须等待
3. **有限等待**：等待进入临界区的进程应在有限时间内进入
4. **让权等待**：不能进入临界区的进程应释放CPU

### 2.3.2 实现互斥的方法

**一、软件方法**

1. **单标志法**：设置一个公用标志turn，turn=i表示允许进程i进入临界区。缺点：违背"空闲让进"。
2. **双标志先检查法**：每个进程设置自己的标志flag[i]。缺点：可能两个进程同时进入临界区。
3. **双标志后检查法**：先设置自己的标志再检查对方标志。缺点：可能产生"饥饿"。
4. **Peterson算法**：结合flag和turn，既能保证互斥又不会饥饿。

**二、硬件方法**

1. **关中断**：进入临界区前关中断，出临界区后开中断。缺点：不适用于多CPU系统，影响系统效率。
2. **硬件指令**：利用Test-and-Set指令（TS指令）或Swap指令（XCHG指令）实现互斥。

### 2.3.3 信号量（Semaphore）

信号量是一种用于进程同步与互斥的工具。主要包括两种原语操作：P操作（wait，申请资源）和V操作（signal，释放资源）。

**一、整型信号量**

```
wait(S): while S <= 0 do no-op; S := S - 1;
signal(S): S := S + 1;
```
缺点：不满足"让权等待"，会出现忙等。

**二、记录型信号量**

```
typedef struct {
    int value;
    struct process *L; // 等待队列
} semaphore;

void wait(semaphore S) {
    S.value--;
    if (S.value < 0) {
        block(S.L); // 将该进程加入等待队列，阻塞自己
    }
}

void signal(semaphore S) {
    S.value++;
    if (S.value <= 0) {
        wakeup(S.L); // 从等待队列唤醒一个进程
    }
}
```

**三、利用信号量实现互斥**

设置互斥信号量mutex，初值为1：
```
wait(mutex);  // P操作
临界区;
signal(mutex); // V操作
```

**四、利用信号量实现同步**

设置同步信号量S，初值为0：
```
// 前驱进程
前操作;
signal(S);

// 后继进程
wait(S);
后操作;
```

### 2.3.4 经典同步问题

**一、生产者-消费者问题**

问题描述：一组生产者进程和一组消费者进程共享一个初始为空、大小为n的缓冲区。生产者向缓冲区放入产品，消费者从缓冲区取出产品。

信号量设置：
- mutex：互斥信号量，初值为1
- empty：同步信号量，表示空闲缓冲区数，初值为n
- full：同步信号量，表示产品数，初值为0

关键要点：
- P(empty)和P(mutex)不能颠倒（可能死锁）
- V(mutex)和V(full)可以颠倒
- P(mutex)和V(mutex)必须成对出现

**二、读者-写者问题**

问题描述：多个读者可以同时读，但写者写时不允许其他读者或写者访问，写者必须互斥访问。

解决方案（读者优先）：
- rcount：读者计数器，初值0
- rmutex：保护rcount的互斥信号量，初值1
- wmutex：写者互斥信号量，初值1

**三、哲学家进餐问题**

问题描述：5个哲学家围坐圆桌，每个哲学家左右各有一根筷子。哲学家需要同时拿到左右两根筷子才能进餐。

解决方案：限制同时进餐人数（最多4个）、奇数号哲学家先拿左筷子偶数号先拿右筷子、或同时拿起两根筷子。

**四、吸烟者问题**

问题描述：三个吸烟者各有一种材料，供应者每次提供两种材料，拥有第三种材料的吸烟者取走并吸烟。

### 2.3.5 管程（Monitor）

管程是一种高级的同步机制，将共享资源和对共享资源的操作封装在一起，每次只允许一个进程进入管程执行过程。

管程的组成：
1. 管程的名称
2. 局部于管程的共享数据结构
3. 对该数据结构进行操作的一组过程
4. 对局部于管程的数据设置初始值的语句

管程中的条件变量：
- wait操作：调用该操作的进程被阻塞，放入条件变量队列
- signal操作：唤醒条件变量队列中的一个进程

## 2.4 死锁

### 2.4.1 死锁的概念

死锁是指多个进程因竞争资源而造成的一种僵局（互相等待），若无外力作用，这些进程都将无法向前推进。

死锁产生的原因：
1. 系统资源的竞争（根本原因）
2. 进程推进顺序非法

死锁产生的必要条件：
1. **互斥条件**：资源只能被一个进程独占使用
2. **不剥夺条件**：进程已获得的资源在未使用完之前不能被剥夺
3. **请求和保持条件**：进程已经保持了至少一个资源，但又提出了新的资源请求，该资源被其他进程占有，此时请求进程被阻塞，但对自己已获得的资源保持不放
4. **循环等待条件**：存在进程资源的循环等待链

### 2.4.2 死锁预防

破坏死锁四个必要条件之一：

1. 破坏互斥条件：将互斥资源改造为可共享使用（如SPOOLing技术）
2. 破坏不剥夺条件：当进程请求新资源失败时，释放已持有的资源
3. 破坏请求和保持条件：采用预先静态分配方法（一次性申请所有资源）或只获得初始资源后才运行
4. 破坏循环等待条件：采用顺序资源分配法（对所有资源编号，按编号递增顺序申请）

### 2.4.3 死锁避免

**一、安全状态与不安全状态**

- 安全状态：系统存在某种进程执行序列，使得每个进程都能顺利完成
- 不安全状态：不存在这样的安全序列，但不一定发生死锁

**二、银行家算法**

银行家算法是一种经典的死锁避免算法，由Dijkstra提出。

数据结构：
- Available：可用资源向量
- Max：最大需求矩阵
- Allocation：已分配矩阵
- Need：需求矩阵（Need = Max - Allocation）

安全性算法：
1. 设置工作向量Work = Available，Finish[i] = false
2. 找到满足Finish[i]=false且Need[i] <= Work的进程
3. 执行Work = Work + Allocation[i]，Finish[i] = true
4. 重复2-3直到所有Finish[i]都为true（安全状态）

### 2.4.4 死锁检测和解除

**一、死锁检测**

资源分配图法：如果资源分配图中存在环路，且环路中的资源类中只有一个实例，则可能发生死锁；如果每个资源类中有多个实例，则环路是死锁的必要但非充分条件。

化简资源分配图：找到既不阻塞又不孤立的进程节点，删除其所有请求边和分配边。若最终所有边都能被删除，则系统不存在死锁，否则存在死锁。

**二、死锁解除**

1. **资源剥夺法**：挂起某些死锁进程，剥夺其资源分配给其他死锁进程
2. **撤销进程法**：强制撤销部分或全部死锁进程
3. **进程回退法**：让一个或多个进程回退到足以避免死锁的地步

### 2.4.5 鸵鸟算法

鸵鸟算法（Ostrich Algorithm）是一种最简单的方法：对死锁问题视而不见。大多数操作系统（如UNIX、Windows）采用此策略，因为死锁发生的概率很低，而处理死锁的代价很大。

# 第3章 内存管理

## 3.1 内存管理概念

### 3.1.1 内存管理的基本概念

内存（Memory）是计算机系统中用于存放程序和数据的部件。内存管理是操作系统最重要的功能之一。

内存管理的功能：
1. **内存空间的分配与回收**：为进程分配内存空间，进程结束后回收
2. **地址转换**：将逻辑地址转换为物理地址
3. **内存空间的扩充**：利用虚拟存储技术从逻辑上扩充内存
4. **存储保护**：保证各进程在自己的内存空间内运行，互不干扰
5. **内存共享**：允许多个进程共享同一块内存区域

**程序装入和链接**

程序运行前需要经过以下步骤：
1. **编译**：由编译程序将用户源代码编译成若干目标模块
2. **链接**：将目标模块和所需库函数链接在一起，形成装入模块
3. **装入**：由装入程序将装入模块装入内存

链接方式：
- 静态链接：运行前将所有目标模块链接成一个完整的可执行文件
- 装入时动态链接：边装入边链接
- 运行时动态链接：需要时才链接

装入方式：
- 绝对装入：知道程序驻留在内存的什么位置，直接装入
- 可重定位装入（静态重定位）：装入时将逻辑地址转换为物理地址
- 动态运行时装入（动态重定位）：地址转换推迟到程序真正执行时

**地址相关概念**

- 逻辑地址（相对地址、虚拟地址）：用户程序中使用
- 物理地址（绝对地址）：内存单元的实际地址
- 地址重定位：逻辑地址到物理地址的转换

### 3.1.2 连续分配管理方式

连续分配方式是指为一个用户程序分配一个连续的内存空间。

**一、单一连续分配**

内存分为系统区和用户区，用户区只存放一道用户程序。最简单，但内存利用率低。仅用于单用户、单任务系统。

**二、固定分区分配**

将用户内存空间划分为若干个固定大小的区域，每个分区装入一道程序。分区大小可以相等也可以不等。

缺点：产生内部碎片（分区内部未使用的空间），分区总数固定限制了并发度。

**三、动态分区分配**

根据进程的实际需要，动态地为之分配内存空间。分区的大小和数量可变。

动态分区分配算法：
1. **首次适应算法（First Fit）**：从空闲分区链首开始查找，找到第一个满足要求的空闲分区。简单快速，但低地址部分产生很多小碎片。
2. **最佳适应算法（Best Fit）**：找到能满足要求且大小最小的空闲分区。产生大量难以利用的小碎片。
3. **最差适应算法（Worst Fit）**：找到最大的空闲分区。产生碎片的可能性较小，但大作业的分配会受影响。
4. **邻近适应算法（Next Fit，循环首次适应）**：从上次找到的空闲分区的下一个分区开始查找。使空闲分区分布更均匀。

**四、动态分区的回收与拼接**

回收分区时需考虑与相邻空闲分区的合并：
- 上邻空闲：与上一个空闲分区合并
- 下邻空闲：与下一个空闲分区合并
- 上下都空闲：三个分区合并

紧凑（Compaction）：通过移动已分配分区中的进程，将多个小的空闲分区拼接成一个大块。需要动态重定位支持。

### 3.1.3 基本分页存储管理

分页存储管理将进程的逻辑地址空间分成若干个大小相等的页（Page），将内存的物理地址空间分成与页大小相等的块（Block/Frame）。以页为单位进行分配。

**一、分页存储管理的基本概念**

- 页（页面）：进程逻辑地址空间的等分块，从0开始编号
- 页框（页帧、物理块）：内存物理地址空间的等分块
- 页表：记录页号到页框号的映射关系，每个进程一张

**二、地址变换机构**

逻辑地址 = 页号 + 页内偏移量
物理地址 = 页框号 × 页面大小 + 页内偏移量

页号P = 逻辑地址A / 页面大小L
页内偏移量W = 逻辑地址A % 页面大小L

地址变换过程：
1. 根据页号查页表，得到对应的页框号
2. 物理地址 = 页框号 × 页面大小 + 页内偏移

**三、快表（TLB）**

快表（Translation Look-aside Buffer，TLB）是高速缓冲存储器，存放最近使用过的页表项。地址变换时先查快表，若命中则可快速得到页框号；若不命中，再访问内存中的页表，并将该页表项存入快表。

引入TLB后有效访问时间 = 命中率 × (TLB访问时间 + 内存访问时间) + (1-命中率) × (TLB访问时间 + 2 × 内存访问时间)

**四、多级页表**

当逻辑地址空间很大时，页表也会很大。采用多级页表可以减少页表对内存的占用。多级页表将页表本身也进行分页，只将当前需要的页表调入内存。

两级页表的地址变换：逻辑地址 = 一级页号 + 二级页号 + 页内偏移

### 3.1.4 基本分段存储管理

分段存储管理将进程的逻辑地址空间分成若干段，每段有段名和段内地址。以段为单位进行分配。

段表：记录段号、段长和该段在内存的起始地址。

逻辑地址 = 段号 + 段内偏移量
段式管理地址变换：根据段号查段表，将段起始地址与段内偏移量相加得物理地址。

分页与分段的比较：
- 页是信息的物理单位，段是信息的逻辑单位
- 页的大小固定，段的大小不固定
- 分页对用户透明，分段对用户可见
- 分页地址空间是一维的，分段是二维的（段名+段内地址）

### 3.1.5 段页式存储管理

段页式结合了分段和分页的优点：先分段，然后在段内分页。

逻辑地址 = 段号 + 段内页号 + 页内偏移

每个进程一张段表，每个段一张页表。

访问一个数据需要三次访问内存：第一次访问段表，第二次访问页表，第三次访问目标数据。

## 3.2 虚拟内存管理

### 3.2.1 虚拟内存的基本概念

虚拟内存（Virtual Memory）是一种内存管理技术，它使应用程序认为它拥有连续可用的内存，而实际上通常将物理内存和磁盘空间共同使用。

虚拟内存的三个主要特征：
1. **多次性**：无需在作业运行时一次全部装入内存，可分多次调入
2. **对换性**：无需在作业运行时一直常驻内存，允许换入和换出
3. **虚拟性**：从逻辑上扩充了内存容量

虚拟内存的实现方式：
- 请求分页存储管理
- 请求分段存储管理
- 请求段页式存储管理

### 3.2.2 请求分页存储管理

在基本分页基础上，增加了请求调页和页面置换功能。

页表项扩展：
- 页号、页框号、状态位（是否在内存）、访问字段（访问次数/时间）、修改位（是否被修改）、外存地址

**缺页中断**：当CPU访问的页面不在内存时，产生缺页中断，操作系统将所需页面调入内存。缺页中断属于内中断（异常），在指令执行期间产生和处理。

**缺页中断处理流程**：
1. 检查页表中该页的状态位，发现不在内存
2. 若内存有空白页框，则直接从外存调入
3. 若内存无空白页框，则选择一个页面换出
4. 若该页被修改过，则写回外存
5. 调入所需页面，更新页表，返回继续执行

### 3.2.3 页面置换算法

当内存中没有空闲页框时，需要选择一个页面换出。选择哪个页面换出的策略就是页面置换算法。

**一、最佳置换算法（OPT）**

选择以后永不使用或最长时间内不再被访问的页面淘汰。这是理论上最优的算法，但无法实现，仅用于性能比较。

**二、先进先出算法（FIFO）**

选择最早进入内存的页面淘汰。实现简单，但可能淘汰经常使用的页面。

**Belady异常**：FIFO算法在增加物理块数后，缺页次数反而增加的现象。

**三、最近最久未使用算法（LRU）**

选择最近一段时间内最久未使用的页面淘汰。性能接近OPT，实现开销较大（需要栈或移位寄存器）。

**四、时钟算法（Clock/NRU）**

对FIFO的改进：为每个页框设置一个访问位，当页面被访问时，访问位置1。淘汰时从当前指针开始检查，若访问位为1则置0并继续扫描，若访问位为0则淘汰该页。

改进型时钟算法：增加修改位，优先淘汰未访问且未修改的页面。

**五、最少使用算法（LFU）**

选择最近一段时间内使用次数最少的页面淘汰。

### 3.2.4 页面分配策略

**驻留集**：分配给进程的物理页框的集合。

分配策略：
- **固定分配**：进程的驻留集大小固定不变
- **可变分配**：进程的驻留集大小可根据情况增减

置换策略：
- **全局置换**：可在整个内存中选择页面淘汰
- **局部置换**：只在进程自己的驻留集中选择页面淘汰

三种组合策略：
1. 固定分配+局部置换
2. 可变分配+全局置换
3. 可变分配+局部置换

### 3.2.5 抖动（Thrashing）与工作集

**抖动**：进程频繁地发生缺页中断，大部分时间用于页面换入换出，CPU利用率急剧下降的现象。

产生抖动的原因：分配给进程的物理块太少，不能满足进程正常运行的基本要求。

**工作集**：在某段时间间隔内，进程实际要访问的页面集合。工作集的大小是动态变化的。

预防抖动的方法：根据工作集大小决定分配给进程的物理块数量。

### 3.2.6 内存映射文件

内存映射文件（Memory-Mapped File）将磁盘文件的全部或部分内容映射到进程的虚拟地址空间，通过访问内存的方式访问文件，由操作系统负责将修改写回磁盘。

# 第4章 文件管理

## 4.1 文件系统基础

### 4.1.1 文件的概念

文件（File）是以计算机硬盘为载体的存储在计算机上的信息集合。文件可以是文本文档、图片、程序等。

文件的属性：
- **名称**：文件唯一标识，以人类可读的方式命名
- **标识符**：文件系统内部的唯一标识（如inode号）
- **类型**：文件类型（如.txt、.exe等）
- **位置**：指向设备和设备上文件位置的指针
- **大小**：文件的当前大小（字节数）
- **保护**：访问控制信息（谁可以读、写、执行）
- **时间、日期和用户标识**：创建、最后修改、最后访问时间等信息

### 4.1.2 文件的逻辑结构

文件的逻辑结构是从用户角度看到的文件的组织形式。

**一、无结构文件（流式文件）**

以字节为基本单位，没有结构。如源程序、可执行文件等。Unix和Windows中的文件都是流式文件。

**二、有结构文件（记录式文件）**

由若干记录组成，每个记录有特定的结构。

- **顺序文件**：记录按某种顺序排列。适合批量存取，查找效率低。
- **索引文件**：为每个文件建立一张索引表，记录关键字和对应记录的物理地址。查找速度快，但索引表占用存储空间。
- **索引顺序文件**：结合顺序文件和索引文件的特点，先分组再建立索引。如ISAM（索引顺序存取方法）。
- **直接文件（散列文件）**：通过散列函数直接将关键字映射到记录的物理地址。查找速度最快，但可能产生冲突。

### 4.1.3 文件的物理结构

文件的物理结构是文件在存储设备上的存放方式，主要涉及文件在磁盘上的分配方式。

**一、连续分配**

每个文件在磁盘上占有一组连续的块。

优点：
- 实现简单
- 支持顺序访问和随机访问
- 磁盘寻道时间少，访问速度快

缺点：
- 文件不能动态增长
- 产生外部碎片
- 需要预知文件大小

**二、链接分配**

每个文件是磁盘块的链表，磁盘块分布在磁盘的任何地方。

**隐式链接**：每个盘块包含指向下一块的指针。文件目录中只有第一块的指针。
- 优点：无外部碎片，文件可以动态增长
- 缺点：只支持顺序访问，不支持随机访问；指针占用空间；可靠性差（一个指针损坏导致整个文件不可用）

**显式链接（FAT）**：将盘块的链接指针统一存放在文件分配表（FAT）中。FAT位于磁盘开头，常驻内存。
- 优点：支持随机访问，速度快
- 缺点：FAT占用较多内存空间

**三、索引分配**

为每个文件分配一个索引块，索引块中存放该文件所有盘块的地址。

- 优点：支持随机访问，无外部碎片，文件可动态增长
- 缺点：索引块占用空间

**多级索引**：使用多个索引块，一级索引指向数据块，二级索引指向一级索引块，以此类推。

**混合索引**：将直接索引、一级间接索引、二级间接索引等组合使用。如Unix的inode结构（12个直接块指针、1个一级间接、1个二级间接、1个三级间接）。

### 4.1.4 文件目录

文件目录是一种数据结构，用于组织和管理文件系统中的文件。

**一、目录的基本概念**

目录项包含：文件名、文件属性（类型、大小、时间等）、文件物理地址（磁盘块号等）。

**二、目录结构**

1. **单级目录结构**：所有文件都在一个目录下。不允许文件重名，查找效率低。
2. **两级目录结构**：每个用户有独立的用户文件目录（UFD），系统有一个主文件目录（MFD）。
3. **树形目录结构**：根目录下可以创建子目录，形成树形结构。
   - 绝对路径：从根目录开始（如/usr/local/bin）
   - 相对路径：从当前目录开始（如./data/file.txt）
4. **无环图目录结构**：允许文件或目录被多个父目录共享。

**三、目录的实现**

1. **线性表**：目录项按线性表（数组或链表）存储。实现简单，但查找效率低。
2. **散列表**：通过散列函数查找，速度快，但需要处理冲突。

### 4.1.5 文件共享

**一、基于索引节点的共享（硬链接）**

多个目录项指向同一个索引节点（inode）。索引节点中有链接计数器，计数器为0时文件才被真正删除。

**二、基于符号链接的共享（软链接/符号链接）**

创建一个链接文件（LINK类型文件），其中存放被链接文件的路径。类似于Windows的快捷方式。

硬链接与符号链接的区别：
- 硬链接直接指向inode，符号链接存储路径
- 删除源文件后，硬链接仍可访问（只要链接计数>0），符号链接失效
- 硬链接不能跨文件系统，符号链接可以

### 4.1.6 文件保护

**一、访问类型**：读、写、执行、添加、删除等

**二、访问控制**：
1. **访问控制矩阵**：行为用户，列为文件，矩阵元素为访问权限。空间开销大。
2. **访问控制列表（ACL）**：每个文件关联一个ACL，记录各用户的访问权限。
3. **用户权限表**：每个用户关联一个权限表。
4. **口令保护**：为文件设置口令。
5. **加密保护**：对文件内容进行加密。

## 4.2 目录

### 4.2.1 目录管理的基本要求

1. 实现"按名存取"：用户只需提供文件名即可访问文件
2. 提高目录检索速度
3. 文件共享：允许多个用户共享文件
4. 允许文件重名：不同目录下的文件可以同名

### 4.2.2 目录结构（详见4.1.4）

## 4.3 文件系统

### 4.3.1 文件系统的结构

文件系统一般包括以下层次：
1. **应用程序**：用户程序
2. **逻辑文件系统**：管理目录结构，实现按名存取，提供文件保护
3. **文件组织模块**：逻辑地址到物理地址的转换
4. **基本文件系统**：向设备驱动程序发送读写命令
5. **I/O控制**：设备驱动和中断处理

### 4.3.2 文件系统实现

**一、文件系统在磁盘上的结构**

- **引导控制块（Boot Control Block）**：包含系统从该卷引导所需的信息。UFS中称为引导块，NTFS中称为分区引导扇区。
- **卷控制块（Volume Control Block）**：包含卷的详细信息。UFS中称为超级块，NTFS中称为主控文件表。
- **目录结构**：用于组织文件。
- **文件控制块（FCB）**：包含文件的详细信息。UFS中称为索引节点（inode）。

**二、内存中的文件系统结构**

- **内存中的安装表**：包含每个已安装卷的信息。
- **内存中的目录结构缓存**：存放最近访问过的目录信息。
- **系统范围打开文件表**：包含每个已打开文件的FCB。
- **进程打开文件表**：每个进程的打开文件列表，包含指向系统范围打开文件表中相应条目的指针。

### 4.3.3 虚拟文件系统（VFS）

虚拟文件系统（Virtual File System）是操作系统内核中的一个软件层，为用户空间的程序提供统一的文件系统接口。VFS支持多种不同的文件系统，将对不同文件系统的操作统一为标准的系统调用接口。

**VFS中的主要对象类型**：
- **超级块对象**：表示一个已安装的文件系统
- **索引节点对象**：表示一个文件
- **目录项对象**：表示一个目录项
- **文件对象**：表示一个进程打开的文件

### 4.3.4 文件系统挂载

文件系统在使用前必须先挂载（Mount）。挂载是将文件系统与目录树中的某个目录（挂载点）关联起来。

### 4.3.5 空闲空间管理

**一、空闲表法**：为每个空闲区建立一条记录。适合连续分配方式。

**二、空闲链表法**：将所有空闲块链接成链表。操作简单但效率低。

**三、位示图法**：用二进制的1位表示磁盘中一个盘块的使用情况。0表示空闲，1表示已分配。占用空间小，容易找到连续空闲块。

位示图所需空间 = 磁盘总块数 / 8 字节。

**四、成组链接法**：将空闲盘块分组，每组第一个盘块记录下一组的盘块号和盘块数。适合大型文件系统，UNIX系统采用此法。

### 4.3.6 文件系统性能优化

**一、磁盘高速缓存（Disk Cache）**：在内存中为磁盘块设置缓冲区。

**二、优化数据的物理布局**：将相关的数据块放在相近的柱面上。

**三、预读（Read-Ahead）**：在需要之前提前将数据读入内存。

**四、延迟写（Lazy Write）**：不立即将修改写回磁盘，而是在稍后批量写回。

### 4.3.7 文件系统的一致性

文件系统一致性检查程序（如fsck）用于检查文件系统的一致性：
- **块一致性检查**：检查磁盘块的使用情况
- **目录一致性检查**：检查目录结构是否完整
- **inode一致性检查**：检查inode的链接计数是否正确

### 4.3.8 日志结构文件系统

日志文件系统（Journaling File System）在修改文件系统元数据前，先将修改操作记录到日志中。如果系统崩溃，可以通过重放日志来恢复文件系统的一致性。如ext3、ext4、NTFS等。

# 第5章 输入/输出（I/O）管理

## 5.1 I/O管理概述

### 5.1.1 I/O设备

**一、I/O设备的分类**

按传输速率分类：
- **低速设备**：如键盘、鼠标，每秒几个到几百字节
- **中速设备**：如打印机，每秒数千到数万字节
- **高速设备**：如磁盘，每秒数十万到数兆字节

按信息交换单位分类：
- **块设备**：以数据块为单位传输，有结构，如磁盘。可寻址，可随机访问任一块。
- **字符设备**：以字符为单位传输，无结构，如键盘、打印机。不可寻址，只能顺序访问。

按共享属性分类：
- **独占设备**：在一段时间内只能由一个进程使用，如打印机
- **共享设备**：可同时被多个进程使用的设备，如磁盘
- **虚拟设备**：通过虚拟技术将独占设备改造成共享设备

### 5.1.2 I/O控制方式

**一、程序直接控制方式**

CPU不断循环检查设备状态寄存器（轮询），直到设备就绪。CPU与I/O设备完全串行工作，CPU利用率极低。

**二、中断驱动方式**

CPU发出I/O命令后继续执行其他任务，当I/O设备完成操作时向CPU发出中断信号，CPU响应中断处理I/O结果。实现了CPU与I/O设备的并行工作。

**三、DMA方式（Direct Memory Access）**

DMA控制器直接控制数据在内存和I/O设备之间的传输，数据传输完成后再向CPU发送中断。CPU仅在传输开始和结束时参与。

DMA方式的特点：
1. 数据传输基本单位是数据块
2. 数据直接从设备到内存（或相反），不经过CPU
3. 仅在传送开始和结束时需要CPU干预

DMA控制器的组成：
- 主机与DMA控制器的接口
- DMA控制器与I/O设备的接口
- I/O控制逻辑
- 命令/状态寄存器（CR）、内存地址寄存器（MAR）、数据寄存器（DR）、数据计数器（DC）

**四、通道控制方式**

通道（Channel）是一种特殊的处理机，有自己的指令系统，专门负责I/O操作。通道通过执行通道程序来控制I/O操作，CPU发出I/O指令后，通道独立完成所有I/O操作。

通道与DMA的区别：
- DMA只能控制一台设备与内存之间的数据交换，通道可以控制多台设备
- DMA只能实现固定的数据传送，通道可以执行通道程序

通道的类型：
- **字节多路通道**：按字节交叉方式为多台低速/中速设备服务
- **数组选择通道**：一段时间内只为一台高速设备服务
- **数组多路通道**：按数组（数据块）交叉方式为多台高速设备服务

### 5.1.3 I/O软件层次结构

I/O软件分为以下四个层次（自上而下）：

1. **用户层I/O软件**：实现与用户交互的接口，如库函数。SPOOLing系统等也在这一层。

2. **设备独立性软件**：实现用户程序与设备驱动器的统一接口、设备命名、设备保护、缓冲管理、差错处理等。关键功能是执行所有设备公共的I/O功能，并向用户层软件提供统一的接口。

3. **设备驱动程序**：与硬件直接相关，负责具体实现系统对设备发出的操作指令，驱动I/O设备工作。每种设备对应一个驱动程序。

4. **中断处理程序**：当I/O设备完成操作时，向CPU发出中断，中断处理程序负责处理中断。位于最底层。

**设备独立性**：用户程序不直接使用物理设备名，而使用逻辑设备名。系统根据实际情况将逻辑设备名映射到物理设备。

### 5.1.4 应用程序I/O接口

应用程序通过以下接口使用I/O设备：
- **字符设备接口**：如get()、put()，用于键盘、打印机等字符设备
- **块设备接口**：如read()、write()、seek()，用于磁盘等块设备
- **网络套接字接口**：如socket()
- **阻塞I/O与非阻塞I/O**：阻塞I/O在数据就绪前挂起进程；非阻塞I/O立即返回，不阻塞进程

### 5.1.5 I/O相关技术

**一、缓冲技术**

引入缓冲的目的：
1. 缓和CPU与I/O设备之间速度不匹配的矛盾
2. 减少对CPU的中断频率
3. 提高CPU和I/O设备之间的并行性

缓冲类型：
- **单缓冲**：在内存中设置一个缓冲区。处理时间=max(C, T)+M，其中C为CPU处理时间，T为设备输入时间，M为数据移入缓冲区时间。
- **双缓冲**：设置两个缓冲区。处理时间≈max(C, T)，进一步提高并行性。
- **循环缓冲**：多个大小相等的缓冲区组成循环队列。
- **缓冲池**：系统中共用的缓冲区集合，分为空闲缓冲区、装满输入数据的缓冲区和装满输出数据的缓冲区。

**二、SPOOLing技术（假脱机技术）**

SPOOLing（Simultaneous Peripheral Operations On-Line）技术将独占设备改造成共享设备，实现了虚拟设备功能。

SPOOLing系统的组成：
1. **输入井和输出井**：磁盘上的两个存储区域
2. **输入进程和输出进程**：负责数据在输入/输出井和设备之间传送
3. **井管理程序**：控制作业与井之间的数据交换

典型应用：共享打印机。多个用户进程的输出先送入输出井，由输出进程逐个打印，用户进程无需等待打印机空闲。

**三、设备分配**

设备分配的数据结构：
- **设备控制表（DCT）**：每个设备一张，记录设备类型、标识符、状态、等待队列等
- **控制器控制表（COCT）**：每个控制器一张
- **通道控制表（CHCT）**：每个通道一张
- **系统设备表（SDT）**：整个系统一张，记录所有设备

设备分配原则：
- 考虑设备的固有属性（独占/共享/虚拟）
- 考虑设备分配的安全性（可能造成死锁）

设备分配算法：先来先服务、优先级高者优先等。

## 5.2 设备独立性软件

### 5.2.1 设备独立性的概念

设备独立性（设备无关性）是指用户程序不直接使用物理设备名，而使用逻辑设备名。系统通过逻辑设备表（LUT）将逻辑设备名映射到物理设备。

设备独立性的优点：
- 方便用户编程
- 提高设备利用率
- 提高系统的可适应性和可扩展性

### 5.2.2 逻辑设备表（LUT）

逻辑设备表（Logical Unit Table）实现逻辑设备到物理设备的映射。每个表项包含：逻辑设备名、物理设备名、设备驱动程序入口地址。

### 5.2.3 设备驱动程序

设备驱动程序的功能：
1. 接收上层软件发来的抽象I/O请求，将其转换为具体命令
2. 检查I/O请求的合法性
3. 检查设备状态
4. 传送必要的参数
5. 启动I/O设备

设备驱动程序的特点：
- 与硬件密切相关
- 每种设备需要一个驱动程序
- 通常由设备制造商提供

### 5.2.4 中断处理程序

中断处理程序的主要任务：
1. 进行进程上下文切换
2. 对中断信号进行测试
3. 启动设备驱动程序
4. 处理中断

中断处理过程：
1. 保存被中断进程的CPU现场
2. 分析中断原因，转入相应中断处理程序
3. 执行中断处理程序
4. 恢复CPU现场，返回被中断进程

## 5.3 磁盘和固态硬盘

### 5.3.1 磁盘的结构

磁盘（Hard Disk Drive）是一种直接存取的存储设备。

**磁盘结构**：
- **盘面（Platter）**：每个盘片有两个盘面
- **磁道（Track）**：盘面上的同心圆环
- **柱面（Cylinder）**：同一位置的多个盘面上的磁道
- **扇区（Sector）**：磁道上的一段弧，通常为512B

**磁盘地址**：由柱面号（磁道号）、磁头号（盘面号）和扇区号组成。

**磁盘访问时间**：
- **寻道时间（Seek Time）**：磁头移动到指定磁道的时间
- **旋转延迟（Rotational Latency）**：扇区旋转到磁头下的时间，平均为转一圈时间的一半
- **传输时间（Transfer Time）**：数据读写的时间

总访问时间 = 寻道时间 + 旋转延迟 + 传输时间

### 5.3.2 磁盘调度算法

磁盘调度算法主要优化寻道时间。

**一、先来先服务（FCFS）**

按请求顺序调度。公平但性能差。

**二、最短寻道时间优先（SSTF）**

选择与当前磁头位置最近的请求。性能好但可能产生"饥饿"。

**三、扫描算法（SCAN，电梯算法）**

磁头从一端向另一端移动，沿途服务请求；到达一端后改变方向。解决了SSTF的饥饿问题。

**四、循环扫描算法（C-SCAN）**

磁头从一端向另一端单向移动，沿途服务请求；到达另一端后直接跳回起始端，中途不服务。等待时间更均匀。

**五、LOOK和C-LOOK算法**

对SCAN和C-SCAN的改进：磁头只移动到最远的请求位置即改变方向（LOOK）或跳回（C-LOOK），不需要移动到磁盘末端。

### 5.3.3 磁盘管理

**一、磁盘格式化**

- **低级格式化（物理格式化）**：将磁盘分成扇区，每个扇区包含头部、数据区和尾部。
- **分区**：将磁盘分成一个或多个柱面组（分区）。
- **高级格式化（逻辑格式化）**：创建文件系统，将初始目录和文件系统数据结构写入磁盘。

**二、引导块**

计算机启动时运行初始化程序（自举程序），该程序通常放在ROM中。自举程序找到操作系统内核，加载到内存并执行。

**三、坏块处理**

- **简单磁盘（如IDE）**：手工处理坏块，如FAT中标记坏块。
- **复杂磁盘（如SCSI）**：控制器维护坏块列表，自动替换坏块。

### 5.3.4 固态硬盘（SSD）

固态硬盘（Solid State Drive）使用闪存（Flash Memory）作为存储介质。

SSD的特点：
- 无机械部件，读写速度快
- 没有寻道延迟和旋转延迟
- 随机访问速度与顺序访问速度相近
- 有写入次数限制（擦写寿命）
- 价格比HDD高

SSD中的磨损均衡（Wear Leveling）：通过均衡分配写入操作来延长使用寿命。

## 5.4 本章疑难点

**1. DMA与通道的区别**

DMA控制器是专门控制数据交换的硬件，其功能简单，只能控制一台设备与内存进行数据交换。通道是一种特殊的处理机，有自己的指令系统，可以执行通道程序控制多台设备。

**2. SPOOLing系统的原理**

SPOOLing系统利用多道程序设计技术，用一个进程模拟外围控制机，将独占设备改造为共享设备。用户进程的I/O操作实际是对磁盘上的输入/输出井的操作，由SPOOLing系统统一负责与物理设备的数据交换。

**3. 磁盘调度算法的选择**

- SSTF：通用，性能较好
- SCAN/C-SCAN：适合请求较多的情景
- 具体选择取决于请求的分布规律

**4. 缓冲与缓存的区别**

- 缓冲（Buffer）：协调速度不匹配的两个设备，数据只使用一次
- 缓存（Cache）：存放经常使用的数据副本，数据可能被多次使用
